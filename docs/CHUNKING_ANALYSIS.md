# 📊 Анализ текущего состояния chunking и рекомендации

> **Дата анализа:** 2025-11-04  
> **Версия:** 1.0

## 🔍 Текущее состояние

### Где происходит chunking?

#### 1. **`src/tools/ingest_kb.py`** (наш код)
- **Функция:** `chunk_text(text: str, max_chars: int = 4000)`
- **Размер чанка:** 4000 символов (жестко закодировано)
- **Перекрытия (overlap):** ❌ НЕТ
- **Стратегия:** Простое разбиение по символам без учета границ

#### 2. **`src/vanna/vanna_pgvector_native.py`** (интеграция с vanna-ai)
- **Методы:** `add_ddl()`, `add_documentation()`, `add_question_sql()`
- **Chunking:** ❌ НЕТ - весь контент добавляется как один чанк
- **Проблема:** Большие документы (до 10MB) сохраняются целиком

### Статистика текущих чанков

| Тип контента | Всего | Средний размер | Медиана | Максимум | Чанков >4K | Чанков >8K |
|--------------|-------|----------------|---------|----------|------------|------------|
| **documentation** | 4,355 | 3,736 символов | 429 | **10,118,161** | 129 (3.0%) | 98 (2.3%) |
| **ddl** | 186 | 1,758 символов | 1,596 | 8,028 | 3 (1.6%) | 1 (0.5%) |
| **question_sql** | 461 | 254 символа | 242 | 536 | 0 (0%) | 0 (0%) |

### Критические проблемы

1. **Огромные чанки документации:**
   - Максимальный размер: **10MB** (10,118,161 символов)
   - 129 чанков превышают 4000 символов
   - 7 чанков превышают 16MB

2. **Нет перекрытий:**
   - Контекст теряется на границах чанков
   - Важная информация может быть разделена

3. **Жестко закодированный размер:**
   - 4000 символов может быть не оптимальным
   - Разные типы контента требуют разных стратегий

4. **Нет учета семантических границ:**
   - Разбиение происходит по символам, а не по предложениям/абзацам

### Важные замечания

⚠️ **Документация:** 129 чанков (3.0%) превышают 4000 символов - требуют разбиения  
⚠️ **Документация:** 7 чанков > 16MB - критическая проблема, нужно немедленно разбить

## ⚙️ Настройки для config.env

```bash
# Chunking Configuration
CHUNK_SIZE_DDL=2949
CHUNK_SIZE_DOCUMENTATION=1139
CHUNK_SIZE_QA=495

CHUNK_OVERLAP_DDL=0
CHUNK_OVERLAP_DOCUMENTATION=113
CHUNK_OVERLAP_QA=0

CHUNK_USE_SMART_BOUNDARIES=true
```

python src/tools/analyze_chunking.py --dsn "$DATABASE_URL" --generate-config

## 🚀 План действий

### Приоритет 1 (критично):
1. ✅ Создать скрипт анализа (`src/tools/analyze_chunking.py`)
2. ✅ Добавить настройки в `config.env.example`
3. ⏳ Вынести настройки chunking в конфигурацию
4. ⏳ Добавить chunking в `add_documentation()` для больших документов (>4000 символов)

### Приоритет 2 (важно):
1. ⏳ Добавить перекрытия (overlap) в `chunk_text()`
2. ⏳ Реализовать умное разбиение по границам предложений
3. ⏳ Разбить существующие большие чанки (>8K)

### Приоритет 3 (желательно):
1. ⏳ Разные стратегии для разных типов контента
2. ⏳ Сохранение метаданных о связи чанков
