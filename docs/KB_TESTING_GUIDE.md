## Тестирование качества базы знаний (KB) и RAG

Цель: автоматизированно проверить, что:
- для вопросов из KB (Q/A) и их перефразов система генерирует SQL, эквивалентный эталонному (Accuracy);
- ретривер подаёт релевантный контент в top-k (hit-rate/MRR);
- сформировать рекомендации по дообучению (чего не хватает в KB).

### Метрики
- Accuracy: доля вопросов, где результат выполнения сгенерированного SQL совпал с эталоном.
- Top-k hit-rate: доля вопросов, где релевантный фрагмент из KB попал в top-k выдачи ретривера.
- MRR (опционально): усреднённая обратная позиция релевантного фрагмента.

### Набор тестов
- Seen: исходные вопросы из KB (content_type='question_sql').
- Paraphrases: 3–10 перефразов каждого вопроса (LLM/шаблоны).

### Критерий корректности
1) SQL валиден синтаксически;
2) результаты выполнения равны результатам эталонного SQL (execution equivalence);
3) (опционально) план выполнения эквивалентен (EXPLAIN).

### Рекомендации (на выходе)
- Недостающие таблицы/колонки/связки (JOIN), часто встречающиеся в ошибках → добавить DDL/Docs/QA.
- Слабые домены (users/payments/assignments) → добавить больше Q/A и документации.
- Низкий hit-rate для типа контента (например, Docs) → доиндексировать/раскрыть описания.

### Запуск
```bash
python -m src.tools.kb_benchmark \
  --database-url "$DATABASE_URL" \
  --openai-key "$OPENAI_API_KEY" \
  --paraphrases 5 \
  --topk 5 \
  --output docs/RETRIEVAL_BENCHMARKS.md \
  --report reports/kb_benchmark_report.json
```

### Выходные артефакты
- Markdown-таблица с агрегатами и примерами: `docs/RETRIEVAL_BENCHMARKS.md`;
- JSON-отчёт с деталями и рекомендациями: `reports/kb_benchmark_report.json`.
