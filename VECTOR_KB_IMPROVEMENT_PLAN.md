# 🧠 План улучшения векторной базы знаний

## 📋 Обзор

Данный документ описывает комплексный план по формированию, тестированию и улучшению векторной базы знаний для NL→SQL системы.

## 🎯 Цели

1. **Повысить качество поиска** в векторке на 30-40%
2. **Увеличить покрытие** бизнес-сценариев до 90%
3. **Автоматизировать процесс** дообучения на новых данных
4. **Создать интерфейс** для тестирования и управления векторкой

## 🛠️ Созданные инструменты

### 1. **Streamlit интерфейс** (`vector_kb_interface.py`)
- 🔍 **Тестирование поиска** - проверка качества семантического поиска
- 📝 **Добавление Q/A** - ручное и массовое добавление Q/A пар
- 🎓 **Обучение** - обучение на DDL, документации, примерах
- 📊 **Аналитика** - метрики качества, статистика векторки
- ⚙️ **Настройки** - конфигурация параметров поиска

### 2. **CLI скрипт** (`qa_management_script.py`)
- 📥 **Добавление Q/A** - `python qa_management_script.py --action add --input qa_pairs.json`
- 🧪 **Тестирование** - `python qa_management_script.py --action test --input qa_pairs.json`
- 📤 **Экспорт** - `python qa_management_script.py --action export --output qa_export.json`
- 📋 **Шаблон** - `python qa_management_script.py --action template --output qa_template.json`
- ⚡ **Эмбеддинги** - `python qa_management_script.py --action embeddings`

## 📊 Текущее состояние векторки

### ✅ Что уже есть:
- **1,247 записей** в векторной базе
- **156 DDL записей** (структура БД)
- **89 Q/A пар** (примеры вопросов и SQL)
- **Семантический поиск** на основе pgvector
- **Гибридный поиск** (семантический + лексический)

### ❌ Проблемы:
- **DDL поиск не работает** - возвращает пустые результаты
- **Контекст перегружен** - слишком много нерелевантной информации
- **Нет few-shot примеров** - отсутствуют примеры для сложных запросов
- **Низкое качество эмбеддингов** - плохая схожесть запросов

## 🚀 План улучшений

### Этап 1: Диагностика и baseline (1-2 дня)

#### 1.1 Анализ текущего состояния
```bash
# Запуск диагностики RAG системы
python start_rag_improvement.py

# Тестирование семантического поиска
python test_semantic_rag.py

# Отладка DDL поиска
python debug_ddl_search.py
```

#### 1.2 Создание baseline метрик
- Измерение точности поиска (precision/recall)
- Анализ времени ответа
- Оценка качества контекста
- Тестирование на стандартных запросах

### Этап 2: Исправление критических проблем (2-3 дня)

#### 2.1 Исправление DDL поиска
- **Проблема**: Семантический поиск не находит релевантные таблицы
- **Решение**: 
  - Улучшение качества эмбеддингов для DDL
  - Добавление нормализации текста
  - Реализация гибридного поиска
- **Тест**: DDL поиск находит релевантные таблицы для 80%+ запросов

#### 2.2 Оптимизация контекста
- **Проблема**: Слишком много нерелевантной информации в промпте
- **Решение**:
  - Умная фильтрация контекста
  - Приоритизация источников
  - Ограничение размера контекста (4000 токенов)
- **Тест**: Уменьшение размера контекста на 30-50% без потери качества

#### 2.3 Добавление few-shot примеров
- **Проблема**: Отсутствуют примеры для сложных запросов
- **Решение**:
  - Создание примеров SQL для разных типов запросов
  - Динамический выбор примеров
  - Адаптация под домен
- **Тест**: Улучшение качества SQL на 20-30%

### Этап 3: Расширение данных (3-4 дня)

#### 3.1 Создание дополнительных Q/A пар
- **Текущее**: 89 Q/A пар
- **Цель**: 150-200 Q/A пар
- **Покрытие**: Все основные бизнес-сценарии

#### 3.2 Улучшение документации
- Добавление описаний бизнес-логики
- Создание схем связей таблиц
- Документирование ролевых ограничений

#### 3.3 Генерация инсайтов
- Автоматическое создание инсайтов о схемах
- Анализ join-графа
- Приоритизация таблиц

### Этап 4: Автоматизация и мониторинг (2-3 дня)

#### 4.1 Автоматизация дообучения
- Скрипт для добавления новых Q/A пар
- Автоматическая генерация эмбеддингов
- Валидация качества новых данных

#### 4.2 Мониторинг качества
- Метрики качества поиска
- Анализ производительности
- Алерты при деградации

#### 4.3 A/B тестирование
- Сравнение старой и новой векторки
- Измерение улучшений
- Выбор оптимальной конфигурации

```bash

source /mnt/ai/src/anaconda3/bin/activate py310
source config.env

# Запуск интерфейса
streamlit run vector_kb_interface.py --server.port 8502 --server.address 0.0.0.0
```

```bash

python qa_management_script.py --action embeddings
```
