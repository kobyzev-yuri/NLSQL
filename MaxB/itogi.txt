



Тестирование показало, что на текущий момент приложение MaxB не может быть использовано для преобразования запросов на естественном языке в полноценные sql-запросы к БД Tradeco.
Сейчас преобразование работает нестабильно (на один запрос может быть выдан разный результат), приложение не распознает смысл таблиц и не знает их состав (не может определить, какие поля присутствуют в той или иной таблице). Также приложение не может формировать WHERE-условия в соответствии с естественным запросом.

Примеры тестирования приложения показаны в папке "РезультатыТестирования". Туда же помещен файл .env с конфигурацией тестового приложения (тот что лежит в корневой папке приложения MaxB_nl2sql_plan).

План работы по исправлениям. 

1.Тестовая среда должна использовать PostgreSQL Server 14 версии (которая используется в 4А-Консалтинг). 

2.Проверить синтаксис команд загрузки моделей
ollama pull qwen2:1.5b
ollama pull qwen2:7b-q4_0
сейчас выполнение команды ollama pull qwen2:7b-q4_0 приводит к ошибке Error: "pull model manifest: file does not exist". 
Поэтому была выполнена команда ollama pull qwen2:7b. Нужно разобраться с правильным наименованием моделей и командами их загрузки.

3.Сейчас в БД Tradeco наименования таблиц и полей часто контринтуитивно и не всегда соответствуют их назначению в бизнес логике. Поэтому в системный промпт надо добавить текстовое описание таблиц и ключевых полей, а также взаимосвязей между таблицами, которое я привел в файле "ОписаниеТаблиц".

4.Результат обработки естественного запроса желательно получить в виде готового SQL-запроса SELECT,  который можно отправить в БД, а не json строки. 

5.Ответы модели нужно тестировать на релевантных для проекта Tradeco тестовых запросах. Примеры подобных запросов и правильных результатов их обработки я привел в файле "ПримерыПромптов".
